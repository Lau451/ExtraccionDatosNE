# Feature: Multi-tenant extraction service + retire legacy HTML

## Objective
Every extraction (licitación, comparativa, orden de compra) must belong to the authenticated user's droguería, and no extraction endpoint may read or write another droguería's data. Retire the legacy HTML screens of the extraction backend (user decision, 2026-09-25: option A).

## Problem (verified 2026-09-25)
- `services/extraccion/supabase_client.py:108` `resolver_drogueria_id_unica` picks env `DROGUERIA_ID` or the FIRST `droguerias` row, used by `persistent_output.py:194` (extraction_results), `persistent_chunking.py:55/119` (sessions, chunks), `procesos_comerciales_client.py:57/97`, `routers/clientes.py:45`. With several droguerías, extractions land in the wrong tenant (oc_sayago.pdf went to "Droguería Test" → presupuestación 404).
- The frontend never sends the JWT to the extraction backend (`frontend/src/lib/api/client.ts:17` `extraccionFetch`); only `POST /procesar` reads an OPTIONAL user (`services/extraccion/auth.py:37`), and only for `subido_por`.
- `GET /api/documentos`, `GET /api/documentos/{id}` and downloads are not filtered by droguería; `PATCH /api/extraction-results/{id}` has no auth.
- Dedup leaks across tenants: `uq_er_sha256 UNIQUE (source_sha256)` is global and RPC `reserve_extraction(p_sha)` (`supabase/migrations/0002_rpc_reserve.sql`) looks up by sha only → a 409 returns another tenant's `extraction_id`.

## Decisions
- User 2026-09-25: retire legacy HTML screens and legacy-only endpoints (historial, CSV downloads `/api/documentos/{id}/descargar` and `/descargar/{archivo}`, `/licitaciones` calendar + `/api/licitaciones/*`, `/guia`, `/`, `/upload`, templates, static). The new frontend is equivalent for extraction: same `POST /procesar`, CSV written server-side to the output folder for licitaciones/comparativas (verified; main vs dev has no behavioral change in what is extracted or where the CSV is written).
- Auth becomes mandatory on every remaining extraction endpoint, reusing `services.shared.auth.get_current_user` (`UsuarioPerfil.drogueria_id`). The droguería is resolved in the request and passed explicitly to background tasks (they have no request context).
- Dedup per droguería: unique `(drogueria_id, source_sha256)` + `reserve_extraction(p_sha, p_drogueria_id)` (new migration 0027 with down). `resolver_drogueria_id_unica` is removed (no silent fallback).
- CSV-on-disk behavior for licitaciones/comparativas must stay identical.
